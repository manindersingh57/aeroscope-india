# AeroScope India | Flask API

Production-oriented Flask service for historical INSAT-3D satellite aerosol-optical-depth analysis.
This is a separate application from the research notebook and **does not retrain ML models**.

## What is included

- Actual location, regional, hotspot, and unified service modules extracted from the provided Colab notebook (Phases 27B, 27C, 27D, 28B).
- Flask application factory, API blueprint, versioned routes, input validation and JSON errors.
- React-compatible restricted CORS, GitHub Actions workflow and pytest route tests.
- Optional geographic map features endpoint, disabled by default until dataset redistribution permission is confirmed.
- **No real project Parquet or hotspot CSV files.** These were not present in the uploaded notebook file itself.

## Quick start on Windows (PowerShell)

```powershell
cd aeroscope-flask-backendackend
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
python -m pytest -q
flask --app wsgi run --debug
```

For macOS/Linux replace activation with `source .venv/bin/activate` and start with `flask --app wsgi run --debug`.

Open `http://127.0.0.1:5000/api/v1/health`: it should respond even without data. `http://127.0.0.1:5000/api/v1/ready` returns 503 until the five data/config files are copied.

## Available endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/v1/health` | Process is serving requests |
| GET | `/api/v1/ready` | Scientific data loaded |
| GET | `/api/v1/overview` | Coverage and hotspot summary |
| GET | `/api/v1/dashboard` | Saved dashboard metadata |
| GET | `/api/v1/location?lat=30.901&lon=75.857` | Nearest grid profile |
| GET | `/api/v1/states` | State list |
| GET | `/api/v1/state-summaries` | All state summaries |
| GET | `/api/v1/states/Punjab` | State profile |
| POST | `/api/v1/compare/states` | JSON `{"states":["Punjab","Haryana"]}` |
| GET | `/api/v1/hotspots/model_a` | Hotspot list, pagination/filtering |
| GET | `/api/v1/hotspots/model_a/summary` | Summary |
| GET | `/api/v1/hotspots/model_a/largest?limit=10` | Largest regions |
| GET | `/api/v1/hotspots/model_a/435` | Region details |
| GET | `/api/v1/models` | Metadata from backend config |
| GET | `/api/v1/map/grid?south=...&north=...&west=...&east=...` | Optional paginated point GeoJSON (disabled by default) |

To use the optional map grid endpoint, set `AEROSCOPE_ENABLE_GRID_API=true` **only after verifying that the exported derived data can be served publicly under your MOSDAC terms**. This endpoint streams normalized point-level summaries, not raw GeoTIFF rasters.

## React integration

Set `VITE_API_BASE_URL=http://127.0.0.1:5000/api/v1` in your React/Vite `.env` and call e.g.:

```javascript
const base = import.meta.env.VITE_API_BASE_URL;
const response = await fetch(`${base}/location?lat=30.901&lon=75.857`);
if (!response.ok) throw new Error(`API ${response.status}`);
const data = await response.json();
```

The Flask app defaults to allowing only `http://localhost:5173`. Override `AEROSCOPE_ALLOWED_ORIGINS` with a comma-separated list of exact frontend origins; never use `*`.

## Deploying the API

Use a Python-capable host, e.g. a Linux container with a persistent data volume. In the `backend/` working directory:

```bash
gunicorn --bind 0.0.0.0:${PORT:-8000} --workers 1 --threads 4 --timeout 120 wsgi:app
```

Start with **one worker** because each worker loads the dataset in memory. Benchmark memory/CPU before increasing workers. Do not rely on Colab as an always-on host. Configure production environment variables and attach protected data externally.

## Scientific and ethics notes

The outputs describe historical aerosol optical depth during **2022-08-23 to 2024-06-05**, not live AQI, ground-level PM2.5, forecasts, or causal source attribution. Geographic and seasonal missingness affect representativeness. Membership strength is not a calibrated probability. Review data-usage rights and attribution before publishing exported features.
